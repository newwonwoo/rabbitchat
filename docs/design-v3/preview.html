이 자산들이 만드는 차이

27개월 아이의 일상에서 가장 자주 발생하는 시나리오(밥 먹기, 목욕, 양치, 손 씻기, 과일 먹기)에 정확히 매핑되는 자산이 이미 다 있다는 게 큰 이점입니다. 부모가 이야기를 만들 때 "오늘 사과 먹은 이야기"를 선택하면 eatapple.png + yummy.png의 두 장면을 자동으로 골라낼 수 있고, 캐릭터의 일관성이 모든 화면에서 유지됩니다.

storyPipeline.ts 자동 매칭 제안

  • 선택지 키워드 → 액션 자산 자동 매칭 테이블 운영
  • 예: "사과" → eatapple, "목욕" → bathtub, "양치" → cleanteeth
  • 매칭 실패 시 → standing.png 또는 happy.png를 fallback
  • 이 매칭은 imageSearcher.ts 1단계(로컬)에서 처리되어 API 호출 0회

왜 hi.png인가

인사하는 포즈가 첫 진입의 정서와 정확히 맞습니다. happy.png(양손 만세)는 너무 흥분된 느낌이고, smile.png는 정적입니다. hi.png는 한 손을 들어 인사하면서 한 손은 차분히 두는 균형 잡힌 포즈로, "안녕, 만나서 반가워"의 정서를 가장 잘 전달합니다.

Child Story 화면 ★

curious.png — 듣는 표정

실사 인형이 만드는 차이

  • 선택지 카드의 이미지가 깡총이 자체 — 외부 스톡 이미지 없이도 "사과 먹는 깡총이", "목욕하는 깡총이", "자는 깡총이"로 시각적 일관성 100% 달성. imageSearcher.ts의 Pexels API 호출이 거의 필요 없어집니다.
  • 아이 인지 부담 감소 — 27개월 아이는 외부 이미지(실제 사과 사진 + 깡총이 표정)를 동시에 처리하기 어렵습니다. 깡총이가 사과를 "들고 있는" 한 장이 훨씬 직관적입니다.
  • 플러시 인형의 따뜻한 질감은 종이책 톤의 베이지 배경 위에서 완벽하게 어우러집니다. 인형 자체의 컬러(#F8F2E5 정도)가 ivory 배경과 거의 동일한 톤이라 자연스럽게 떠 있는 느낌.
  • 그림자 보존 — 이미지 하단의 자연스러운 그림자가 "공간에 존재하는 인형"의 무게감을 줍니다. 별도 그림자 처리 불필요.

3데이터 흐름 — 아이 재생 중 API 호출 0
부모 검토 → optimize
  • LLM 호출 (시나리오 생성)
  • 이미지 검색 (4단 체인 작동)
  • TTS 호출 (spokenLine → audio)
  • 모든 결과 IndexedDB 저장
  • publish 시 cache warm-up
아이 story 재생
  • 신규 LLM 호출 없음
  • 신규 이미지 검색 없음
  • 신규 TTS 호출 없음
  • IndexedDB hit only
  • 로컬 자산 hit only

cacheWarmer.ts 책임: optimize 단계에서 모든 자산을 선처리·캐싱하여 재생 시 hit rate 100% 보장.

4IndexedDB store 구조 (4개)
tts
TTS 음성 캐시. 재생 시 hit 우선.
key: hash(text+voice)
llm
LLM 응답 캐시. 동일 프롬프트 재호출 방지.
key: hash(prompt)
img
이미지 검색 결과 캐시 (Pexels 등).
key: hash(query)
character
로컬 캐릭터 자산 매핑 + fuzzy match.
key: keyword

lib/storage 위치에 4개 store를 명시적으로 분리. 단일 store 통합 금지 — TTL과 invalidation 정책이 다름.

5sanitizeCharacterVoice — 깡총이 ≠ 엄마

깡총이는 엄마 목소리로 말하지만 엄마가 아닙니다. "엄마가", "엄마 말", "엄마는" 같은 자기-3인칭 표현은 클라이언트 전달 전 차단·치환합니다.

엄마가 동물원에서 사자를 봤어
→
우리가 동물원에서 사자를 봤어
엄마는 너를 사랑해
→
너를 정말 사랑해
엄마 말 잘 들었지?
→
잘 들어줘서 고마워

characterVoice.ts → sanitizeCharacterVoice(text)로 항상 통과. LLM 응답·spokenLine·audioFile 자막 모두에 적용.

자산 보강 우선순위 (촬영 추가가 가능하다면)

  • 1순위 — listening: 귀를 살짝 앞으로 기울이고 눈을 크게 뜬 정면. child story 메인 표정이라 가장 자주 등장.
  • 2순위 — thinking: 한 손을 턱에 대고 살짝 위를 보는 포즈. 부모 검토 화면, 로딩 상태에 활용.
  • 3순위 — jumping: 양 발 모두 공중에 뜬 점프샷. 정답·완료·축하 모먼트.
  • 1·2순위 두 컷만 추가해도 시각적 풍부함이 크게 늘어납니다.

톤 조정이 필요하다면

  • 인형의 흰 배경이 거슬린다면 → 모든 자산의 흰 배경을 투명 PNG로 사전 처리 (이 시안은 이미 그렇게 처리됨)
  • 인형이 너무 정적이라면 → CSS body-wobble 모션을 항상 적용 (transform: translateY 0 → -6px 호흡 애니메이션)
  • 이야기마다 다른 깡총이가 필요하다면 → 시나리오 기반 자산 자동 매칭 활용 (eatapple → 사과 먹기 이야기)
